# ADR-001 A74. The board goes live per team before the ledger

*Adds to:* A60, A44, A30, A2. Recorded with NERD-5533, from the user's decisions of 2026-11-18: things typed into the boss's input box annoy them most, and nothing may become less visible than it is.

- **The key.** `notices.delivery`: `typed`, the default, or `board`. It is set in the shared `[notices]` table or a project's `[projects.<p>.notices]`, never in a repo file (A46). The daemon reads it once at start (A19). Set in the shared table, it switches every tabs team without a table of its own. The ◆ spaces are always typed. `config resolve` shows the shared value for them too, and the daemon ignores it there.
- **The rule.** For a tabs team whose key is `board`, the daemon remembers the agent last seen on the pane in its boss place that bears the boss's name.
  - `claude`: the boss's notices and messages go to its board.
  - Another agent: they are typed, as A30 and A44 say, until a Codex boss has a wake (NERD-5562).
  - None seen since the daemon started: they are held in the inbox, neither typed nor posted, until one is. Held messages count toward the user's alert.
  - A poll that names no agent (`agent.list` failed, or the boss exited) changes nothing remembered. So a Claude boss that exits keeps its board, and a Codex boss is never posted to.
  - A boss name two teams share is typed.
- **Messages.** The messages queued for a board-mode boss are posted oldest first, at most 100 a transaction (`store.MaxQueuePost`), each row marked delivered in it; while more remain the dispatcher runs its next pass at once, until none remains. A drain's passes also retry refused prompts, once a pass; bounded by one pass per 100 backlog rows.
  - Workers', panes' and bosses' go on the `team` channel, as `post`, or as `returned` with the worker it was for.
  - The daemon's go on the `daemon` channel, as `undelivered`, `returned` or `notices`.
  - A post takes its message's id, unless a post already holds it.
  - A body over 8 KiB is posted in parts.
  - A row the board still refuses is failed, with an `undelivered` post and no notice to its sender.
  - A row being typed is left alone.
  - A post that fails leaves the rows queued for the next pass, never typed.
- **`send`** answers as before, with the message's id and state `queued`; the post follows in the dispatcher's next pass. To a board-mode boss there is no typed fallback: `unknown_op` and `daemon_unavailable` mean "wait for the daemon", not `herdr agent prompt`.
- **The guarantees are A44's until B1.**
  - A stop loses what the Batcher holds, and a GitHub event can be told twice.
  - Context levels, `unknown` and the start notice are told again after a restart.
  - One thing is gained: a committed post cannot be lost the way a typed notice can (A2's timeout and crash rules).
- **What the boss runs.** `herdr-agentisan board wait` in the background. When it ends: `board read`, then wait again. A wait started late answers at once for every post past the boss's mark, so nothing is missed while none runs.
- **Dormant acknowledgement rules.** `BoardPending` excludes acknowledged posts and waiting messages and reports the latest acknowledgement of a post on the project or of this boss's waiting messages. A waiting message counts again when either its sequence or its last update exceeds the corresponding cutoff for that project and boss.
  - A newer acknowledgement during an episode resets the alert count at its own time, capped at the poll time. A boss's read in that poll is timed at the poll. The next alert is due at the later of `every` after the reaction and the first alert's time for what is still pending.
  - When the user acknowledges a ceiling that has set a deadline and a later ceiling remains, the next alert is still due by that deadline.
- **Later.** B1 replaces the notices bullet's sink with the ledger's admission and `PostAdmitted`. It keeps the key, the rule and the messages path (B2's core).

# ADR-001 A44. Boss notices from the team poll

*Adds to:* D1, D7, D9 and A21. Recorded with NERD-5325 (G7 of the parity inventory), part 1 of 2. Part 2 delivers through the inbox and adds a mute, once NERD-5256's second PR delivers messages.

- **The daemon only informs.** A notice tells the boss what herdr shows. The daemon never acts on one (D1): it does not prompt, rotate, restart or retire a worker. Stall detection is limited to a blocked status; transcript ages and process checks stay in agentisan.
- **What is told.** Each poll diffs its model against the last one, as A21's status events do:
  - a worker that turned blocked, or left the team (its pane closed, or moved out of every place the team's resolver knows, or its agent exited and left the pane a shell, which agent.list no longer names), at once. An exit is told whether or not the pane's status changed with it: `<worker>'s agent exited (pane <id>)`. A poll whose `agent.list` failed knows no names, so it cannot tell an agent herdr knows only by name from a shell: it keeps each agent pane as the last poll judged it, named as it was. The next poll that answers tells the exit, and a close or a status change meanwhile is told under the worker's name;
  - a worker that turned unknown and still is at the next poll;
  - a worker whose turn ended: its terminal's `completion_seq` in `agent.list` changed to a new value. herdr sets it when an agent goes from working or blocked to idle, and clears it at the agent's next change (`src/app/actions.rs:22-29,1720-1728`), so it is compared, never ordered. A terminal is compared only with itself: a reissued pane id, a terminal seen for the first time and one that came back are each a baseline. A poll whose `agent.list` failed compares no turns and keeps them. A turn that ends and a next one that starts within one poll is not seen.
  - Covered: every agent pane a team places in a group, bound or not. Never: the boss's own panes, or plain shells.
- **Restarts.** The first poll after a start is the baseline, and each team's boss is told once that the daemon started and that turns that ended while it was down are not reported. Nothing is kept across a restart.
- **The lines.** A turn's line has no status: `pane.list` is read before `agent.list`, so the pane's status can be the poll's before the turn ended. Each names the worker (its logical id when a row binds it, else the name herdr knows its agent by, else its pane), then its reported ctx, item and stage (D4), each with control and format characters made spaces and cut to 80 characters: `ha-coder-2 finished a turn · ctx 44% · NERD-5322 · verify`.
- **Pace.** A team's notices are coalesced: a poll's go out together, and its boss gets at most one message per `gap`; what comes sooner waits and goes with the next. The same worker and kind again within `repeat` is dropped, except a turn's end, the start line and a context level, whose source keeps its own memory per level. A message holds at most 8 KiB, the inbox's cap (`store.MaxBody`); past it the oldest lines are cut, and the message says how many.
- **Configuration (D9).** `[notices]` in the shared file, or `[projects.<p>.notices]`: `skip`, the kinds not told (`turn_ended`, `blocked`, `unknown`, `gone`, `started`, and NERD-5261's context levels `ctx_soft` and `ctx_hard`; `ctx_ceiling` is refused, since the ceiling always reaches the boss, D7); `gap`, seconds from 0 to 3600, default 30; and `repeat`, seconds from 0 to 86400, default 300. The daemon reads them once at start from the shared file, as A29 reads the github repo; the repo file is not read. `[notices]` belongs to the user's layers only (the shared file, a project's own table, `--set`), since it shapes what the boss is told: a repo file that sets it is refused (an unknown key), so `config resolve` never shows a value the daemon ignores. A file that does not resolve is logged and every team gets the defaults.
- **Delivery, part 1: the log.** Each message is one Info line in `daemon.log` (JSON, as `daemon run` always writes it; a daemon whose log level is set above info writes none), `"message":"notice"`, with `project`, `notices` (the lines) and, when lines were cut, `dropped`. A boss follows it with `tail -F <state dir>/daemon.log | grep --line-buffered '"message":"notice"'`; the log rotates by rename, which `tail -F` follows. Nothing is queued in `messages` before NERD-5256 delivers them: queued rows are never pruned, and would all be typed into the boss on the day delivery ships.
- **Part 2: the inbox.** Each message goes to the team's boss through `send`'s store (A2), appended to a daemon notice still queued for that boss, so a boss that is away gets one notice, not a pile. `notices mute <worker>` silences a worker for a while (in memory, default 1 h, at most 24 h); like `skip`, it covers the soft and hard context levels, never the ceiling.
- **One path for every source.** Every notice goes through the same per-boss pacing, and `Kind` is open to a new source's kinds. Whose pane a notice is about is the source's choice: the poll's leaves the boss's own panes out, while the Batcher and the sink drop nothing for being the boss's, so NERD-5261 can tell the boss about its own context. `team.Pane` carries pane.list's `terminal_id` for such sources. A notice can carry an acknowledgement, run once it is settled: sent in a message the sink accepted, skipped, or a repeat. G8 (NERD-5326) records its seen-set there; NERD-5261's context levels are another source.
- **Cutover (D2).** wait-done.sh and herdr-watch-v2.sh retire once a boss following the log has seen a shift's turns, blocks and departures match theirs. boss-stall-watch.sh's transcript checks stay in agentisan.

# ADR-001 A44. Boss notices from the team poll

*Adds to:* D1, D7, D9, A2, A21 and A30. Recorded with NERD-5325 (G7 of the parity inventory), in two parts: part 1 tells and paces, into daemon.log; part 2 delivers through the inbox, and adds a mute and the end of a block.

- **The daemon only informs.** A notice tells the boss what herdr shows. The daemon never acts on one (D1): it does not prompt, rotate, restart or retire a worker. Stall detection is limited to a blocked status; transcript ages and process checks stay in agentisan.
- **What is told.** Each poll diffs its model against the last one, as A21's status events do:
  - a worker that turned blocked, or left the team (its pane closed, or moved out of every place the team's resolver knows, or its agent exited and left the pane a shell, which agent.list no longer names), at once. An exit is told whether or not the pane's status changed with it: `<worker>'s agent exited (pane <id>)`. A poll whose `agent.list` failed knows no names, so it cannot tell an agent herdr knows only by name from a shell: it keeps each agent pane as the last poll judged it, named as it was. The next poll that answers tells the exit, and a close or a status change meanwhile is told under the worker's name. A pane keeps its last name only across a poll that cannot name it: one whose `agent.list` failed, or answered listing neither the pane nor its terminal, as when its agent exits between the poll's `pane.list` and `agent.list` reads. A terminal `agent.list` lists with no name runs an agent nobody named, and a new terminal in the pane a new agent: either is told by its pane (NERD-5365). A pane that turns blocked on a poll whose `agent.list` failed, which that poll cannot judge an agent (one herdr knows only by name), is told blocked at the first poll that judges one there and finds it still blocked, under the name that poll gives it. One no longer blocked, gone or judged a shell by then is not told;
  - a worker that turned from blocked to working, idle or done, at once: `<worker> is no longer blocked`. One that turns unknown is told as unknown, and one that leaves as gone. The end of a block never told, as above, is not told;
  - a worker that turned unknown and still is at the next poll;
  - a worker whose turn ended: its terminal's `completion_seq` in `agent.list` changed to a new value. herdr sets it when an agent goes from working or blocked to idle, and clears it at the agent's next change (herdr 0.9.5 `src/app/actions.rs:22-29,1754-1762`), so it is compared, never ordered. A terminal is compared only with itself: a reissued pane id, a terminal seen for the first time and one that came back are each a baseline. A poll whose `agent.list` failed compares no turns and keeps them. A turn that ends and a next one that starts within one poll is not seen.
  - Covered: every agent pane a team places in a group, bound or not. Never: the boss's own panes, or plain shells.
- **Restarts.** The first poll after a start is the baseline, and each team's boss is told once that the daemon started and that turns that ended while it was down are not reported. Nothing is kept across a restart.
- **The lines.** A turn's line has no status: `pane.list` is read before `agent.list`, so the pane's status can be the poll's before the turn ended. Each names the worker (its logical id when a row binds it, else the name herdr knows its agent by, else its pane), then its reported ctx, item and stage (D4), each with control and format characters made spaces and cut to 80 characters: `ha-coder-2 finished a turn · ctx 44% · NERD-5322 · verify`.
- **Pace.** A team's notices are coalesced: a poll's go out together, and its boss gets at most one message per `gap`; what comes sooner waits and goes with the next. The same worker and kind again within `repeat` is dropped, except a turn's end, the start line and a context level, whose source keeps its own memory per level. A message holds at most 8 KiB, the inbox's cap (`store.MaxBody`); past it the oldest lines are cut, and the message says how many.
- **Configuration (D9).** `[notices]` in the shared file, or `[projects.<p>.notices]`: `skip`, the kinds not told (`turn_ended`, `blocked`, `unblocked`, `unknown`, `gone`, `started`, and NERD-5261's context levels `ctx_soft` and `ctx_hard`; `ctx_ceiling` is refused, since the ceiling always reaches the boss, D7); `gap`, seconds from 0 to 3600, default 30; and `repeat`, seconds from 0 to 86400, default 300. The daemon reads them once at start from the shared file, as A29 reads the github repo; the repo file is not read. `[notices]` belongs to the user's layers only (the shared file, a project's own table, `--set`), since it shapes what the boss is told: a repo file that sets it is refused (an unknown key), so `config resolve` never shows a value the daemon ignores. A file that does not resolve is logged and every team gets the defaults.
- **Delivery: the inbox (A2, A30).** Each message goes to its team's boss, `<short>-boss` or the ◆ spaces' `boss`, as a message from the daemon in `state.db`, which the dispatcher types into the boss once its agent is in its place. A boss that is away gets one notice, not a pile: while the daemon's notice to that boss is still queued, each message is appended to it, in one transaction (`store.Notify`), keeping its id and its place in the inbox. So a line added later still reaches the boss before a message queued after the notice began: the notice's order is its lines', not the inbox's. A notice of a failed delivery is never appended to, nor one the dispatcher has claimed: the next message is a new notice.
  - **The body.** A daemon's message starts `[agentisan` and takes no reply: `[agentisan] notices:`, then one line per notice, oldest first. Past 8 KiB (`store.MaxBody`), header included, the oldest lines are cut, and the header counts every notice cut so far: `[agentisan] notices (3 earlier dropped):`. The newest line always stays. Each line is one line of valid UTF-8 with every control character a space. A queued body that is not one the daemon wrote is not appended to.
  - **In the same pass.** A poll queues its notices before it gives the dispatcher its model, which wakes it, so a boss in its place has them in that pass.
  - **The log as well.** Each message is still one Info line in `daemon.log` (JSON; none when the log level is above info), `"message":"notice"`, with `project`, `notices` (the lines), `dropped` when lines were cut, `boss`, and, once queued, `inbox` (the notice's id) and `appended`. A boss can follow it with `tail -F <state dir>/daemon.log | grep --line-buffered '"message":"notice"'`, and it is the only record of a message for a project no team's boss is configured for, which is settled, since the daemon reads its teams once. A message whose write fails is logged, not settled, so a source that acknowledges, such as G8's, tells it again.
  - **Events (A21).** A new notice is an `agentisan.message.queued` event, from the daemon to the boss; an append is none.
- **Mute.** `herdr-agentisan notices mute <worker> [--for 1h]`, `notices unmute <worker>` and `notices list`, the daemon's `notices.mute`, `notices.unmute` and `notices.list` ops, each with a budget of 5 s and A23's output: one JSON object, exit 1 when refused.
  - A worker is named as its notices name it: its logical id when a row binds it, else its agent's name, else its pane id, in any team. A name no group worker of the poll's last model has is refused (`unknown_worker`), so a typo mutes nothing; with no model, before the first poll or after one whose lists failed, `not_ready`, which the client asks again within A52's window: at most 20 s, the window, the budget and an exchange. The boss is no group worker.
  - A mute drops every notice about the worker of a kind `skip` can name, so never the ceiling, and acknowledges it; a dropped notice never counts toward `repeat`. The boss's own context lines are about no worker.
  - It lasts an hour by default, at most 24 hours (`bad_request` past that), until its end, exclusive. Muting again sets its end anew; an unmute says whether a mute was in force. Mutes are held in memory, so a restart clears them.
- **One path for every source.** Every notice goes through the same per-boss pacing, and `Kind` is open to a new source's kinds. Whose pane a notice is about is the source's choice: the poll's leaves the boss's own panes out, while the Batcher and the sink drop nothing for being the boss's, so NERD-5261 can tell the boss about its own context. `team.Pane` carries pane.list's `terminal_id` for such sources. A notice can carry an acknowledgement, run once it is settled: sent in a message the sink accepted, skipped, muted, or a repeat. G8 (NERD-5326) records its seen-set there; NERD-5261's context levels are another source.
- **Cutover (D2).** wait-done.sh and herdr-watch-v2.sh retire once a boss has seen a shift's notices, turns, blocks, their ends and departures, match theirs. boss-stall-watch.sh's transcript checks stay in agentisan.

## A44 addendum: a new agent's unknown, and the project a notice names

*Narrows:* "a worker that turned unknown and still is at the next poll". Recorded with NERD-5254, from the agentisan-skills cutover's findings F3 and F4.

- **A new agent's unknown waits 20 polls (F3).** `ag-qa-1's status is unknown` reached the boss seconds after a healthy spawn. A pane seen for the first time reads as a change from absent, and herdr had not yet classified the agent `worker spawn` waited for, so two polls of unknown told it. Now the two-poll rule covers only an agent pane seen in a known status (working, idle, done or blocked) since its terminal last changed. One never seen known since then is told unknown only at the 20th poll in a row that judged it to run an agent, about a minute at the 3 s poll, counting from the first such poll (the daemon's first included), and once. A pane that stops running an agent, closed or left a shell, is forgotten, and an agent that starts there again is counted from 1. So is a pane whose terminal changes, as a live handoff reissues it under the same pane id (NERD-5365): the agent there is a new one, counted from 1, and an unknown pending for the old one is not told.
- **A notice names its team's project as the poll names it (F4).** The ◆ spaces' project is `spaces.project`, `""` while it is unset. During the cutover the old ◆ boss's notices carried `agentisan` while `spaces.project` named it, then `""` once it was unset and `agentisan` had become a tabs team. Each was right for its configuration. A log filter on a project that changed layout also finds its old layout's lines.

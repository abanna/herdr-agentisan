# ADR-001 A49. Focus from the poll

*Adds to:* the A28 addendum's "When it is sent". Recorded with NERD-5346, the QA debt from NERD-5309. Its herdr lines are as of v0.9.5, where the cited code is unchanged from v0.9.3.

- **The poll is a source of focus.** herdr moves focus without a `pane.focused` event when a terminal client navigates: a client connects in `ClientShell` mode (`src/server/headless.rs:1945-1946`), and its navigation ends in `accept_current_focus_without_events` (`src/server/headless/client_views.rs:472, :938`, `src/server/headless.rs:2621`, `src/server/headless/notifications.rs:607`), which records the new focus as already announced and emits nothing (`src/app/api.rs:824-831`), so no later sync announces it either (`:876-909`). Whether the user's own keys and clicks take that path is NERD-5309's live check. So each team poll also takes the workspace of the pane its `pane.list` lists focused, and the view follows a move no event announced within one poll (`polled`, `internal/daemon/view.go`). A list with no pane focused changes nothing.
- **An event is newer than a list.** The poll reads how many focused workspaces the focus collector has recorded before it lists the panes, and takes the list's focus only when the collector has recorded none since. An event or a resync that lands while the poll is listing wins, so a list read before it never moves the view back; the next poll's list agrees with it.
- **A poll forgets nothing.** Unlike a resync, a poll that finds focus where it was leaves the view last sent as sent, so it sends nothing: the same view is sent again only after a failed call or a resync, as before.
- **Back is unchanged.** The focus history in `state.db`, and Back's walker, still take only events and resyncs: a poll's focus says where focus is, not when the user moved it.

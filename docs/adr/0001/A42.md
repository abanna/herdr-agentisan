# ADR-001 A42. Item and stage from every role's own turns

*Amends:* D4's "Agentisan pushes item and stage", A6's "Agentisan stays their only writer", the `item` and `stage` writer cells of the token contract, and Report commands. Recorded with NERD-5334 part 1. The Codex side was checked against the codex-rs source at `rust-v0.161.0`, the Claude side against the Claude Code hooks reference.

- **A second command, the same writer.** `report turn` runs as an async `UserPromptSubmit` and `Stop` hook under Claude or Codex, and sets the tokens `report stage` sets, with source `agentisan` and the 24 h TTL (A5). Both are the agent reporting itself from its own pane, so D4's one writer per key holds: the agent writes, through Agentisan's steps and through its turn hooks. herdr's last write wins, so a turn's closing status replaces the stage of the step before it.
- **The lines.** The agent states its item and stage in its own text; nothing is inferred.
  - The stage is the final message's closing line when it opens `BOSS:` or `STATUS:`, less the prefix, so `BOSS: blocked: 1Password agent` reports `blocked: 1Password agent`. It is the closing paragraph's last line, or the line just before that paragraph's trailing `item:` lines. A paragraph ends at a line of white space only, so a closing code fence is part of one and a status inside the fence never counts. `BOSS:` is the line a worker ends each turn with; `STATUS:` is for a pane with no boss above it, such as the boss's own.
  - The item is an `item: <id>` line: the first in a prompt, as the boss's dispatch carries it, or the last in the final message's closing paragraph, as the boss names its own.
  - A line counts once `*` and backticks are dropped, so Markdown bold and code ticks may wrap it. White space runs become one space, other unprintable characters are dropped, and a value over 80 characters is cut to 79 and `…`. A value is never refused for its characters, unlike `report stage`'s, because the agent cannot be told.
- **A new item clears the stage.** An item stated with no stage that differs from the item the pane carries (read from `pane.list`) also reports `stage` empty, which herdr takes as a clear, because that stage belonged to the old item. The same item only renews its TTL, and so does any item on a pane `pane.list` does not show, such as an alias trusted with no lineage, whose item is unknown.
- **What reports nothing:**
  - a turn that states neither: clearing then would wipe a pipeline step's stage every turn;
  - a hook inside a subagent, which carries `agent_id` under either agent (`SubagentCommandInputFields` in `hooks/src/schema.rs`; Claude's common input fields);
  - an event other than the two;
  - a Claude turn the user interrupts, which runs no `Stop`, and one that ends on an API error, which runs `StopFailure` instead;
  - a Codex memory consolidation's `Stop`, which runs no user, project, session-flag or plugin hook at all (`select_handlers` in `hooks/src/events/stop.rs`).
- **Placement.** The payload proves nothing about which agent ran the hook, so the lineage decides. A lineage with a Codex process or an app-server in it, or one whose arguments cannot all be read, must pass `CheckCodexHost` (A25), so a hook the shared app-server runs reports nothing and Codex needs `codex --no-daemon`. Codex runs a hook as `$SHELL -lc` in a session of its own, with no sandbox (`build_command` in `hooks/src/engine/command_runner.rs`), so the report reaches herdr under the default sandbox, which A25's `report stage` from a tool command cannot. Any other lineage lands through `ResolvePane` (NERD-5268), as Claude's statusline does. A nil lineage, off Linux and darwin, trusts `HERDR_PANE_ID` unless `CODEX_THREAD_ID` is set.
- **Opt-in.** The hooks are sample config, `docs/config/claude-hooks.example.json` and `docs/config/codex-turn-hooks.example.toml`, and agents write the lines only when their instructions say so. The Codex ones are a sample of their own, each hook in a group of its own: A43's `codex hooks` installs exactly the three `ctx` hooks of `docs/config/codex-hooks.example.toml`, and refuses `report codex` beside another hook in one group. It does not install the turn hooks. `worker spawn` (NERD-5254 part 4b) starts its workers without them: spawn passing the hooks to its workers is a NERD-5254 follow-up that no part holds yet.

## Part 2: an old stage ages

*Adds to:* the token contract, A5's TTL table, A18's snapshot contract, A23's idle clock, A28's sidebar rows and its addendum, and A23's `team status`. Recorded with NERD-5334 part 2. A stage stays on its pane for up to 24 h (A5), long after the turn it named has ended. herdr gives no token a time, so the stage's writer now records one, and the daemon ages the stage instead of clearing it.

- **`stage_at`.** Whenever `report stage` or `report turn` writes a stage, it also writes `stage_at` in the same report: the report's time in whole Unix seconds, in canonical decimal. A cleared stage clears `stage_at` too.
  - An item alone never writes it. The boss's `item:` dispatch at `UserPromptSubmit` would otherwise make every old stage look reported at the start of each turn.
  - A reader takes only that spelling: a positive count of seconds with no sign, space or leading zero (`report.ParseStageAt`). A value after the reader's clock counts as no `stage_at` at all.
- **Stale.** A stage is stale when all four hold:
  - the pane is at rest (idle or done);
  - the daemon saw its latest working stretch begin and end;
  - the pane still holds the stage it held when that stretch began;
  - its `stage_at` is before that stretch began.

  A stage reported at the end of a turn therefore stays current while the pane rests, even when the value repeats (`waiting: boss` twice). A working or blocked pane is never stale.

  A pane herdr detects no agent in has a stale stage whatever the clock saw, with or without `stage_at` (F3, as A27 does for `ctx`). Anything unknown counts as current, never as a false alarm:
  - no `stage_at`, as from an older binary;
  - a stretch the daemon didn't see whole, as after a restart;
  - a stage that changed during the stretch, which herdr's own `pane report` does without a `stage_at`.
- **The stretches.** `IdleClock` (A23), which the poll feeds and `team status` reads, also records each pane's latest working stretch. So the snapshot, the sidebar and `team status` give one answer from the same inputs (`team.StageOf`).
  - A stretch begins at the last poll that saw the pane at rest, since the stretch began somewhere after that poll. A report made in a turn's first seconds therefore counts as inside the turn. Blocked counts as part of the stretch.
  - Only a rest-then-work change the daemon saw starts a stretch. A pane first seen at work needs a rest, a stretch and a rest again. An unknown status, or a pane gone from the model, makes the clock forget the pane.
  - `stage_at` is in whole seconds, so the stretch's start is truncated to the second, and a report in that second counts as inside the stretch.
  - The clock times only the panes a team places, so a pane outside every team keeps a current stage unless F3 holds. Rests (`idle_s`, `idle_since`) are timed as before.
- **The snapshot.** Each row, the boss's included, gains `stage_at` (RFC 3339, UTC) and `stage_stale` (a bool, left out when false). Both keys are optional and additive, as A37's `idle_since` was. An older dashboard refuses the newer snapshot, the same version skew A37 and A38 accepted.
- **The sidebar.** Every poll, beside the ctx display and in the same report, the daemon writes each agent pane's stage into one of two keys:
  - `stage_now`: a current stage as the pane's `stage` token holds it;
  - `stage_old`: a stale stage, then ` · ` and its age in one coarse unit (`12m`, `3h`, `2d`), or ` · stale` when the age is unknown. The stage is cut with `…` so the whole value fits herdr's 80 characters and the age always shows.

  Each push sets both keys, the one not in use empty. `docs/config/herdr-sidebar.example.toml`'s agents line 2 becomes `$item $stage_now $stage_old`. G2's colour rules move onto `stage_now`, and `stage_old` is dimmed with no rule, so an old `blocked` never shows red (F4). With no daemon running, the sidebar shows no stage: the keys expire about 9 s after it stops, the cost the ctx bands already accepted.
- **The dashboard.** A stale stage, in a row, on the boss line and in the group view, takes no G2 colour (F4). It is drawn dim, faint and italic, which no current stage is. Not every terminal draws faint or italic, so the words say it too:
  - a row's time column reads `3h05m ago`, or `stale`, where a current stage shows how long it has been held. The time column is the first to drop on a narrow dashboard; the words then move into the stage cell (`buil… · 3h05m ago`, `buil… · stale`, or the time alone), kept whole while the stage is cut;
  - the boss line adds ` · 3h05m ago`;
  - the group view reads `reported 3h05m ago`, or `stage stale`, in place of `in stage 12m`.
- **`team status`.** Each member gains `stage_stale` and `stage_at` (RFC 3339, or null), by the same rule.
- **Accepted gaps:**
  - A turn or a rest shorter than one 3 s poll can be missed, and the stage then stays current.
  - A stage that some other writer changes during a stretch and then changes back to the value it held at the stretch's start reads as unchanged.

| Key | Writer | Target | Format | TTL |
| --- | --- | --- | --- | --- |
| `stage_at` | `report stage`, `report turn` | Agent pane | Unix seconds of the stage's report, canonical decimal; written and cleared with `stage` | 24 h, with `stage` (A5) |
| `stage_now`, `stage_old` | Daemon | Every agent pane | The current stage, or the stale stage and ` · <age>`; one set, the other empty | About 9,000 ms, with the ctx display |

Budget: an agent pane a team places now carries 11 keys, and the daemon's push sets 6, still inside herdr's 16 per report and 32 per target.

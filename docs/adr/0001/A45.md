# ADR-001 A45. Boss notices from the GitHub collector

*Adds to:* A1, A29 and A44. Recorded with NERD-5326 (G8 of the parity inventory), part a of 2. Part b adds reviews: each new one, with the P-badge counts of its body and inline comments.

- **What is told.** After each successful open-PR list of a project's repo, the collector diffs it against `state.db` and tells the project's boss, through A44's Batcher and sink:
  - `merged`, keyed by the merge commit. A PR that left the list is looked up with `gh pr view <n> --repo=<repo> --json=state,mergeCommit`. A closed PR leaves silently. One still open, or a lookup that failed, is looked up again the next interval.
    - At most 10 lookups per repo per collection, lowest number first.
    - A list that comes back at its limit of 100, counted before release-please's are skipped, may be cut off, so it looks nothing up.
    - No merged list is read: `gh pr list --state merged` sorts by creation, so a long-lived PR merged now falls past any small limit. So a PR opened and merged between two successful collections, the daemon running or not, is never in the open set, and its merge is not told.
  - `ci_failed` and `ci_passed` (A29's CI rule), and `dirty`, a merge conflict, each keyed by the head commit. A new push can fail or conflict again. A rerun that fails again on a head already told sends nothing; that gap is accepted, since a fix is a new push.
  - `approved`, the first 👍, once per PR.
- **The fields.** A29's call gains `headRefOid`. The header and snapshot v1 are unchanged.
- **Once per event (A1, migration 0004).** `github_seen` holds every event told, by project, repo, PR, kind and key; `github_open` the open PRs of the last successful collection; `github_seeded` the repos whose first collection was recorded. Keys carry the project as well as the repo, so two projects on one repo are each told.
  - **The seed.** A repo's first successful collection records what is true then and tells nothing, so G8 does not tell every open PR's history the day it ships. The mark keeps a later restart from seeding again.
  - **Recorded when told.** An event is recorded in its notice's acknowledgement (A44), once the sink accepted its message or its kind was skipped; a merge resolves its PR in the same transaction. A refused message, the size cut, a failed write, or a restart before the flush records nothing, and the event is told again: a duplicate, never a loss. A notice handed over is held for its project's `gap` plus one interval, so it is not handed twice meanwhile.
  - **Restarts.** What happened while the daemon was down is told at its first collection, including the merge of a PR that was open at its last one.
  - **Failures.** A failed list tells nothing and changes nothing, so it never reads as every PR closing.
  - **Pruning.** A row the collector has not observed for 30 days goes in the daily prune. An open PR's rows are observed at each collection; a merged PR's go 30 days after the merge, and a repo no longer configured ages out.
- **No GitHub free text.** The lines carry PR numbers, 7-character oids, counts and the repo name from the configuration, never a title, branch, body or comment: anyone who can open a PR on a public repo would otherwise type into the boss's session. `herdr-agentisan #50 merged as 1e0fb1b`, `#50 CI failed at 1e0fb1b (2 of 7 checks)`, `#50 CI passed at 1e0fb1b`, `#50 has a merge conflict at 1e0fb1b`, `#50 got a 👍`.
- **Pace and configuration.** The five kinds are paced per project like A44's, but never dropped as repeats: the seen-set tells each once, and CI failing again at a new head inside `repeat` is news. `notices.skip` can name each; a skipped event is recorded all the same, so a boss that stops skipping a kind is not told the old ones.
- **The goroutines.** The collector runs the gh calls and the diff on its own goroutine, after the header's two calls, so a slow lookup never delays that repo's header. It does delay the repos collected after it, and the next collection: a repo's lookups take up to 10 gh calls of up to 15 s each. Meanwhile the header keeps each repo's last good state for 5 intervals. It hands the notices to the team poll through a queue; the poll adds them to its Batcher before each flush, and the acknowledgements run there.
- **Cutover (D2).** boss-pr-watch-v3.sh, a second GitHub poller beside the daemon's, retires once a boss following the log has seen a shift's merges, CI and 👍 match its own. Its Codex review notices wait for part b.

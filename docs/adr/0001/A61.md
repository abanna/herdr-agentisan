# ADR-001 A61. A restarted agent's ctx

*Amends:* A27's "D7 and the dashboard are to count `ctx` only on a pane where Herdr detects an agent", which guarded only an agent that exits. *Adds to:* D4's token contract, with `ctx_at`, and A56, whose rule and clock it applies to `ctx`. Recorded with NERD-5510 (Codex parity P8, R41, area B1).

- **The gap.** A Codex's `ctx` lives 24 h (A27), and nothing clears it when the agent exits. An agent restarted in the same pane therefore showed the previous session's last `ctx` as its own until its first count: the boss's pane, `codex resume`, a hand start. The sidebar band, the dashboard, `team status` and CtxWatch all read it. A spawned worker is not hit, since each spawn opens a new tab; nor is a rotation's replacement, a new split. A Claude restarted in a pane showed the old one's for up to 180 s.
- **The token.** Every report that sets `ctx` sets `ctx_at` in the same report, with ctx's source and TTL: Unix milliseconds from the reporting process's clock, `model_at`'s format (`report.FormatModelAt`). `report statusline` and `report codex` share the writer, `report.push`. A report with no count, which pushes the model alone, sets neither.
  - **Why not `model_at`.** It is written only by a report that carries a model, so it dates the model, not the count. `report codex` pushes the model alone when the session's transcript holds no count yet (`ErrNoContext`), and Claude's statusline does the same before Claude has measured its context: likeliest in a new session's first report. That gives the pane a fresh `model_at` beside the previous session's `ctx`, which a gate on `model_at` would take for current.
  - D4's one writer per key is unchanged: `ctx_at` has the same writer as `ctx`.
- **The rule** (`team.CurrentCtx`): a pane's `ctx` counts while herdr detects an agent in it (A27), and its `ctx_at` is no earlier than that agent's process start, A47's, which the poll's launch-model cache reads (A39). Otherwise it is unknown: `ctx  --` in the sidebar, `ctx` null in the snapshot and in `team status`, and no level for CtxWatch.
  - **A56's fallback.** Where no start is known, the `ctx` counts, as before. That covers a budget miss, a miss asked again after 60 s, a pane in no team (the cache asks only team panes), and an OS with no start time. A `ctx` with no `ctx_at` counts too, unlike A56's model, which counts only with its `model_at`: a build before this one wrote `ctx` with none, which lives up to 24 h after the install.
  - **A56's clock.** The start is never after the true one, and the stamp is in milliseconds, so a report made after the agent started is never read as older than it.
- **Every reader, one gate.** The poll reads the agents' starts first, whether or not its agent list was read. It then gates the model's `ctx` (`team.GateCtx`) before the idle clock, the notices, CtxWatch, the snapshots and the sidebar read it. A team pane's band comes from the gated model; a pane in no team keeps its own token, having no start to gate it by.
  - The poll shares its starts, with the terminal each pane showed, through a `team.StartClock`. `team status`, which reads herdr itself, gates each member's `ctx` by it, as fresh as the last poll. A pane id herdr reissued to another terminal gets no start.
- **Unchanged:** A27's exit case, CtxWatch's memory by terminal and its re-arm, the snapshot contract v1 (`ctx` was always nullable), the model's gate, and `report turn`, which writes neither key.

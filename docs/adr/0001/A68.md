# ADR-001 A68. A snapshot row's agent: the provider on every row

*Adds to:* A18's snapshot contract (a new optional key), A39 and A58's model column (its fallback) and A37's group view (its model line). Recorded with NERD-5524 (Codex parity P23, row R42, part of NERD-5501), from the user's answer Q13 (2026-10-23): the provider is shown on each row. Before it, a row said which provider ran in it only through its model's name. A Codex started without `-m` has no model until its first hook (A39), so its row said nothing. A18's, A37's, A39's and A58's text is kept as written.

- **A new optional key, `agent`,** on every row, the boss's included: the agent herdr's `pane.list` detects in the pane, as herdr sent it (`team.Pane.Agent`, which `team status` already gives as `agent`).
  - It is an open string, not a closed enum. herdr detects more agents than the plugin launches, so a closed set would make the daemon write a snapshot the dashboard refuses as soon as a team's pane ran one of them. `TestSnapshotCarriesTheProvider` sends `gemini` through the daemon's op and decodes the answer strictly.
  - Absent, empty or null, it means not reported: herdr detects no agent. It is absent for a shell, for a pane herdr knows only by name, and for every row of a snapshot written before the key existed.
  - Nothing else fills it: no name, no launch command line.
- **The contract stays v1.** The key is optional and additive, with A18's `unnamed` as the precedent, and decoding stays strict.
  - A re-cased key, a second `agent` or a value that is not a string is refused.
  - So is a shell that carries an agent: a shell is a pane where herdr detects none (A38).
  - Every snapshot written before this amendment decodes, and draws, as it did.
  - A reader built before it refuses a snapshot carrying the key, `unknown key "agent"`, the skew A37, A38 and A42 accepted. Reopen open dashboards after installing and `daemon-restart`.
- **The overview's model column falls back to the agent.**
  - A row with no model shows its agent in the model's place, dim, so it reads as a provider and not a model.
  - It is made safe to draw, trimmed, and cut to the column's six cells: `claude` is six, `codex` five.
  - The column is as wide as what it draws, so a group where no row has a model still draws it.
  - A row with a model shows the model as before; its family already names its provider (A58).
  - The column costs no cells it did not already take. On the user's 97-cell pane the stage keeps its width (`codex_97x40`).
  - The column drops where it dropped before, and the fallback with it.
- **A group's view names the agent ahead of the model** on each box's model line: `codex · sol6.1  ctx ▓▓▓░░░░░░░ 33%`, the agent and the dot dim, the agent cut as in the overview.
  - With no model it reads `codex  ctx …`, and with no agent it reads as before.
  - The title, which is cut first, is unchanged.
- **Not drawn:**
  - the boss line, which shows no model either, so the boss carries the key unread until a Codex boss's line draws both;
  - the tab bar.

  Search does not match the agent: A20's fields are unchanged.

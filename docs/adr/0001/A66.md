# ADR-001 A66. A spawn chooses its worker's provider, and each row records it

*Adds to:* A62's "a spawn may choose the other (P18)", A23's `worker spawn`, A35's `workers` rows and A50's task packet. *Changes:* A50's "a packet preferring the other provider is refused", and the code a boss's `--model` of the other provider gets with routing off (A62's `config_invalid`, for a model only the boss chose). Recorded with NERD-5519 (Codex parity P18, rows R4 and R6, part of NERD-5501), from the user's decision Q2 (a) and the boss's answers to its Stage 3, Q1 to Q10 (2026-10-23). A50's and A62's text is kept as written.

- **The provider a spawn runs.**
  - The order is `worker spawn --provider claude|codex`, else the task packet's `provider_preference`, else the type's default provider (A62).
  - `--count n` spawns n workers of one provider.
  - `team up` takes no provider: it fills each group with its default, counting the workers of the other provider already there (per-provider counts are NERD-5521's).
  - The workforce chooses the provider before routing is asked, and routing routes within it (A50).
- **Refused before anything opens:**
  - **`bad_request`:** a `--provider` that is neither claude nor codex, and a packet whose `provider_preference` is neither. The packet's refusal never quotes it.
  - **`provider_mismatch`:** a `--provider` the packet's preference disagrees with, whether or not routing is on. The provider is the spawn's choice, not routing's, so the refusal is not only recorded while routing is off, as routing's own are.
  - **`provider_refused` (new):** a provider the worker type cannot run yet (A62's gaps: a codex debugger and a claude reviewer). Its message names what lifts the gap. A type whose own default is refused stays the configuration's error, `config_invalid`.
- **`--model` checks the provider and never chooses it** ("never silently change provider", the rules' `provider_selection`).
  - **Routing on:** a binding of the other provider is `provider_mismatch`, from routing's own check (A63). The answer adds that `--model` never chooses the provider, so pass `--provider` too.
  - **Routing off:** a `--model` whose name says the other provider runs it (A62's `ModelFamily`) is `provider_mismatch` too, naming both families and never the model. Before, it was `config_invalid`, which sent the boss to a configuration that was fine.
  - A model the configuration gives keeps `config_invalid`.
- **Changed with routing off:** a packet preferring the other provider used to be recorded as a refusal routing would have made, and the spawn launched the type's default. It now launches the preferred provider, as A62 says.
- **Every `workers` row records its provider** (migration 0008).
  - `provider` is claude or codex: the agent its launch ran. It is written at every bind, spawn and `team up` alike, whether or not routing decided the launch. So rotation (NERD-5520) and status read it rather than infer it.
  - `BindWorker` refuses a bind without one.
  - A bind of a retired or lost id writes it afresh; a handoff keeps it.
  - The migration copies `routed_provider` into it where routing launched the row. Routing never changes the provider, so that is the one the row ran. Every other row bound before it stays NULL: nothing recorded which agent it was launched as.
  - `routed_provider` stays the decision's own record.
- **`team status` shows each row's provider** (the user's decision Q13), beside the agent herdr detects in the pane, so a pane running another agent than its worker was launched as shows. It is on each bound member and each unbound row. A pane no row binds, and a row bound before 0008, has none. The dashboard's key is P23's (NERD-5524).
- **`config resolve --project` checks every provider a type may run** for the user's overrides (A63's pair check). Before, it checked only the type's default provider (A62's "until P18"). Now it checks every provider but those the type cannot run yet, since `--provider` or a packet may choose either. So an override that would refuse a spawn of a type under its other provider is refused there too: for example, a disabled `codex_strong` for `pre_check` while `precheck` runs claude by default.
- **The routed event's `agentisan.routing.provider`** is the provider the worker runs, chosen as above. Its schema is unchanged.

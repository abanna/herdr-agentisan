# ADR-001 A33. Rotation: the handoff token

*Amends:* A5's `handoff` row, whose writer is now the daemon. *Adds to:* A23, with a command the daemon runs, and A21, with an event. Recorded with NERD-5261 (item 5b), part 1b of its PRs. Part 1a tells the boss about context levels. Part 2 adds `worker spawn --replaces`, the handoff's acknowledgement, the I2 gate, retire's handoff guards and I5's test.

## Part 1b: the handoff token

- **The daemon is the writer.** A worker that has written its handoff runs `herdr-agentisan handoff ready`, and the daemon sets the `handoff` token on its agent pane. This closes A5's row: "the writer is `hready.sh` until worker rotation (item 5b) lands, then the daemon". `retire --after-handoff` reads the token as before.
- **What is written.**
  - The value is `⟳ READY TO RESTART`, the one `hready.sh` writes, so `$team`'s `⟳r` and the sidebar read either mark the same.
  - The source is `agentisan`, and the TTL is 24 h, herdr's longest. herdr keeps each key's TTL apart (`metadata_tokens.rs`), so `ctx`'s 180 s from the same source does not touch it.
  - `--clear` writes an empty value, which removes the token, with no TTL.
  - The token is written even when the pane already carries the value. herdr keeps one value per key, and the last write wins across sources, so the daemon's write replaces a mark `hready.sh` left and gives it the TTL.
- **Which pane.** Resolving the target never changes a `workers` row, unlike retire's.
  - A live row's logical id names the pane herdr lists with the row's terminal (A35). A row bound to no pane, whether lost, with no terminal or with one herdr lists nowhere, is `unknown_worker`.
  - Otherwise a tabs team's worker tab label names its agent pane, and then a pane id names its pane, a stale one as `pane.process_info` resolves it.
  - With no target, it is the pane the command runs in, as its process lineage confirms it, unless herdr lists it with no terminal; else the pane of the live row `HERDR_AGENTISAN_WORKER` names, else `bad_request`.
  - The pane must be an agent pane in a team's group, in a tabs team or the ◆ spaces: one herdr detects an agent in, or knows one by name, as a held agent keeps its name. The boss's place, a shell and a pane in no team's group are `not_a_worker`. A boss hands off by its own protocol.
  - The command takes no `--project`: a logical id, a tab label and a pane id each name one pane on the server.
- **Proven before written.** The daemon writes only once `pane.get` shows the pane still has the terminal it read. A pane gone, showing another terminal or listed with none is `pane_changed`, and nothing is written. `retire --after-handoff` trusts the mark, so a mark on a reissued pane id would close the wrong worker.
- **The answer.** `{id, bound, project, group, pane_id, ready, changed}`, with the worker named as the team model names it: its logical id, or its pane id while no row binds it. `changed` is false when the pane already carried that value. Its other refusals are the codes every workforce op shares, such as `not_ready` (A35), `herdr_failed`, `config_invalid` and `store_failed`. The budget is 10 s, and the daemon's workforce lock serializes it with itself and with retire's close.
- **The event.** `agentisan.worker.handoff`, with step `ready` or `cleared`, records each mark the command changed; one that changed nothing records none (`docs/telemetry.md`). Part 2 adds the handoff's other steps.
- **The `hready.sh` cutover.** `hready.sh` wrote its mark with no TTL, so a mark it left never expires (Linear comment ae2380f6). The daemon never sweeps them on its own (D1). At the cutover:
  1. Workers stop running `hready.sh` and run `handoff ready` instead.
  2. The boss finds the marks left, from `$team`'s `⟳r` or `herdr pane list`.
  3. For each, `handoff ready <id>` adopts a mark still meant, with the TTL, and `handoff ready <id> --clear` removes one that is not.
- **Codex.** Under Codex's sandbox a tool command cannot reach the daemon's socket, so a sandboxed Codex worker cannot run `handoff ready`, and its boss marks it (A43).

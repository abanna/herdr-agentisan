# ADR-001 A23. The workforce commands

*Adds to:* D1, D11, I1 and item 4. Recorded with NERD-5254, on A19's team model, in six parts: `team status` (part 1, this amendment's first bullets), `worker retire`, the configuration `worker spawn` reads, `worker spawn`, `team up` with the team's dashboard, then the tdaddy preflight (I8, A10) and AGENTS.md's tdaddy wording. Each part adds its bullets here.

- **Over the socket.** The workforce commands are daemon ops (`team.status`, `team.up`, `worker.spawn` and `worker.retire`) that take their request as `args`. The command parses, asks and prints. Reading a request keeps the 5 s exchange; each op then has its own budget, from one table the daemon and its client both read: 100 s for a spawn, a spawn's for `team up`, whatever that is, 10 s for status and retire, 1,500 s for `retire --after-handoff`. An op past its budget while a call fails answers `timeout`; a code that says more, such as `handoff_timeout` or `herdr_gone`, stands. An op runs under the daemon's lifetime, not its connection, so it finishes when its client has gone, and a daemon stopping ends it. The skill's wrapper waits 120 s, and 1,800 s for a handoff; A52 sizes the spawn's budget, which team up shares, so that its not_ready window, the budget and an exchange fit in 115 s of that.
- **Every op reads the configuration afresh**, so an edit to `herdr-agentisan.toml` applies to the next one, and it resolves the project's profile with its D12 checks. The team poll still reads it once, at start (A19).
- **The team.** `--project` names it. Without it, the team is the tabs team whose workspace holds the caller's pane (`HERDR_PANE_ID`, counted only when one of its pane's processes is in the command's own lineage, as a report's pane is, since herdr can reissue a closed workspace's ids), else the only tabs team, else the op is refused with `bad_request`. `team status` reports the `[spaces] project` too when `--project` names it; its groups are its ◆ spaces. With `--project` the caller's pane is never looked up, and `worker retire` needs no team.
- **Status.** One record per group, configured or found: its workers, slots, occupied and open counts, targets and members. A slot is occupied by every agent pane of the type, recorded or not, and by every pane a live `workers` row binds there, whose agent may still be starting; open is slots less occupied, never below 0. Each member has its id (its row's, else its tab's label), whether a row binds it, its pane, agent, status, `ctx` (null unless a percentage), `item`, `stage` and `idle_s`, how long the daemon has seen it idle or done. The boss's panes are listed apart, by pane id. `idle_s` comes from an in-memory clock the team poll feeds from `pane.list`'s statuses, so a failed `agent.list` does not stop it; after a restart it starts again, and a team the poll does not know, one added since the daemon started, has none until it restarts.
- **The configuration `worker spawn` reads.** It resolves with its checks, so `config resolve` shows it and refuses a mistake in it, all but a command named by a path, which spawn refuses before it opens anything (the agent, below). Its commands and `[spawn]` keys come only from the user's own layers; a repo file sets no more of it than the groups' counts and the models, top-level or a group's (A46). A group may set its own `agent`: with a command, a type runs that command and that group's model only; otherwise `review` runs `codex --no-daemon`, which A22 requires for a Codex worker's `ctx` (its item and stage also need A25's `--sandbox danger-full-access`, a launch setting NERD-5278 owns), and every other type the top-level `agent.command`, with the group's model or the top-level one. The `debugger` type always runs claude with the plugin's read-only launch (A32), with its group's model, else the top-level one when the top-level command is claude's: its group may set no command, which resolve refuses, and the top-level command never applies to it, since a flag there, such as a permission mode, would lift the launch's fence. A group's command passes D12's check, and no command, the top-level one included, may carry `--model`, `-m`, `--name`, `-n` or `--effort`, or for Codex a `-c` or `--config` setting `model` or `model_reasoning_effort` (A50), which the workforce sets, even with its value attached (`-mo3`). `[spawn]` holds `shell_prompt` (a regular expression, which herdr matches with Rust's `regex` syntax; resolve compiles it with Go's `regexp`, a first check only, so a construct Rust lacks, such as a literal `{` or `\Q…\E`, passes here and fails the spawn), `shell_ready_keys` (no empty name) and `shell_ready_after_s` (0 to 60, default 3). A group's `slots` is at most 64, so a mistyped cap can open no flood of tabs.
- **The worker.** Its logical id is `<short>-<type>-<n>`, with the lowest `n` from 1 not taken by one of the team's tab labels, by an agent name anywhere on the server, by a live row, or by any row of another project, retired or lost too: one id has one row across every project, so its queue and handoffs stay that project's, and a spawn takes the next `n` (QA #78 F4). A project renamed keeps its old rows, and the messages still queued for them, which no boss is configured to receive, are kept. The id is its tab's label, its herdr agent name and Claude's `--name`, and it must fit herdr's agent-name grammar, `^[a-z][a-z0-9_-]{0,31}$`, or the spawn is refused with `invalid_id`. Each worker gets one tab in the team's workspace, never focused, with the repo as its cwd and `HERDR_AGENTISAN_WORKER=<id>` in its shell's environment. A team with no workspace gets one, labelled with the project's name, whose first tab becomes the first worker's.
- **Slots.** A type's slots are taken by every agent pane in its tabs, recorded or not, and by every pane a live row binds there. A spawn past `slots` is refused whole with `slot_cap`, naming the cap: "coder is capped at 3 slots (herdr-agentisan.toml): 2 occupied, 2 requested". A type with no group, or with one that only describes (A36), is `unknown_group`.
- **The preflight.** Before anything opens, and outside the workforce lock, a spawn runs A34's check on the project's repo: `Hooks.Preflight`, `preflight.HostCheck` when none is set. A refusal is `preflight_failed`, with the check's message saying what to fix. So is a repo the configuration changes to while the check runs: tabs open only in the repo it checked.
- **The agent.** A Codex worker planned while Codex's ctx hooks are not all installed, or `config.toml` turns hooks off, is a warning beside the result, never a refusal (A43); the daemon checks the `CODEX_HOME` of its own environment. `--model` overrides the type's model, held to A46's rule for a model (`ErrBadRequest`, before the preflight). Spawn resolves the model, and an effort, before it plans the launch; NERD-5289's routing will make that choice instead, in the same place. Whatever chose them, the model is checked again where spawn passes it, and an effort must be 1 to 16 lowercase letters. Neither refusal holds the value. herdr's `agent.start` runs its own executable for the kind from the shell's PATH, so the command's first element must be a bare `claude` or `codex`: a path would be silently swapped for whatever is on PATH, and is refused. The arguments are the rest of the command, then `--no-daemon` for Codex when the command lacks it (A22; Codex refuses it twice), `--model`, the effort (`--effort` for Claude, `-c model_reasoning_effort="…"` for Codex; none until routing) and, for Claude, `--name`.
- **Readiness.** Every tab opens and every row binds as `starting`, with its pane's terminal (A35), under the workforce lock. A lost row's id is free again and rebinds at its next generation; any other live row's id stays taken, since the team poll may still re-key it. The agents then start at once, outside it, and spawn waits for them as the herdr CLI does: `agent.get` by name until the agent is ready, failing when it is blocked, exits, is another kind, or loses its name or terminal. A Codex that is blocked fails with a hint naming its hook review and its directory-trust prompt, and so does one whose screen shows the hook review, which herdr does not report as blocked: a prompt typed into it would pick a choice. `agent.start` is retried for 10 s while the pane's shell is not at its foreground, and `pane.get` must show the worker's terminal before each retry, since `agent.start` takes only a pane id, which herdr can reissue. A worker that does not come up has its pane closed, once `pane.get` shows it still has the worker's terminal, and its row marked failed, and the op answers `spawn_failed` naming it; the others stay. The workers up are marked active first, then every other is cleaned up at once, all on one 4 s budget of their own, which fits in the 5 s the exchange leaves a reply past the op's budget, so an op its deadline ended still answers (QA #78 N1). Each failed row is written before its pane is closed, so a herdr too slow for that budget can leave a pane open, which `team status` shows, but never a row starting, which would hold its slot. A herdr call the op's deadline ends is out of time, never `herdr_failed`, even in the instant before the op's context marks itself done (QA #78 R1).
- **A shell that asks at startup.** herdr's own check only sees which program has the terminal, and a shell asking a question itself, such as oh-my-zsh's update prompt, still has it: `agent.start` would type its command line into the question. `[spawn] shell_prompt`, a regular expression one line of the prompt matches, makes spawn wait for that line first (`pane.wait_for_output`). `[spawn] shell_ready_keys` (default none) are sent once to a pane that is still not ready after `shell_ready_after_s` (default 3) and has a program at its foreground, such as a password prompt. They are never sent while the shell itself has the terminal. A shell profile can also skip its questions when `HERDR_AGENTISAN_WORKER` is set.
- **Rows.** `workers` statuses are `starting`, `active`, `retired`, `failed` and `gone`, beside A35's `lost`; the last three set `retired_at`, never before the row's creation. Reusing a retired or lost id of the same project rebinds its row: the new pane, terminal and group, the next generation, `retired_at` cleared and the shell left for the team poll to read (I1, A35). Any other live id, and any id of another project, is never rebound, which the store refuses too. A status write lands only on the generation it was read at, and `starting` or `active` never brings a lost row back.
- **Retire.** The target is a logical id or a pane id, which herdr resolves when it is stale. A live row's id names the pane herdr lists with the row's terminal (A35), since the row decides who a worker is; a live row bound to no pane, lost or with its terminal listed nowhere, is retired with nothing closed (`unbound`), unless its handoff is pending, which is refused with `handoff_pending`, since ending the row would strand the handoff. A worker tab's label in a team's workspace names its pane only for an id no live row has, and with a shell split beside its agent it closes the agent's pane. Whichever names the pane, the row bound to its terminal is the one retired. A pane in a team's `<short>-boss` tab is refused with `not_a_worker`, and a name nothing holds with `unknown_worker`. Retire closes the pane once `pane.get` shows it still has the terminal it read, and marks the row retired; a pane that moved meanwhile closes nothing and is refused with `pane_changed`, a terminal herdr lists nowhere any more marks the row gone, and a retired id answers `changed: false`. `--after-handoff` first waits, without the workforce lock, polling every 2 s, for a non-empty `handoff` token on the pane with that terminal (A5), and closes it at the id it has then. A terminal that goes while it waits is the worker gone. No token in time is `handoff_timeout`, with the pane left open. A debugger writes no handoff (A32), so `--after-handoff` on a debugger's row bound to a pane is refused at once with `bad_request`, before any wait; an unbound one is retired with nothing closed, as above. The daemon does not ask the worker for its handoff; the boss does, before it runs the command.
- **The output.** On every path stdout is exactly one JSON object, `{"ok":true,"data":…}` or `{"ok":false,"error":{"code","message"}}`, and the exit is 1 when refused. That includes flag errors (`bad_request`) and a daemon that cannot be reached (`daemon_unavailable`). A command not built yet is absent, so the skill's wrapper reports it unavailable: until their parts, `worker spawn --replaces` (item 5b) and `boss handoff` (item 6).
- **Team up (part 5).** It fills every configured group, in the team model's type order, up to its `workers` count: it opens `workers` less occupied, counted as a spawn counts slots, and never more, so a team already full gets nothing (I9) and no fill passes a cap, since `slots` is never below `workers`. A group that only describes is skipped (A36). The preflight runs first, outside the lock, as for a spawn, and so does the repo check, and before it a debugger group's launch, as a spawn's (A32): one it cannot build refuses the whole team up only when a debugger is to open. Every worker's tab opens under one lock, with ids taken from one pool, then the dashboard, then all the agents start at once, as a spawn's do. The answer lists each group's `workers`, `occupied` (before the fill) and `spawned`, then the workers up. A worker that does not come up answers `spawn_failed` naming it, as a spawn does; the others stay, and `team status` shows them.
- **The team's dashboard (part 5).** `team up` opens one when the team's workspace has none: a pane there labelled `<short>-dashboard`, or with the dashboard entrypoint's title, "Agentisan dashboard", as one prefix+d opened, counts and is left as it is. Otherwise it splits the boss's pane, the first agent in the `<short>-boss` tab as the snapshot names the boss, down with the plugin's dashboard entrypoint, unfocused (`plugin.pane.open`, herdr 0.9.5 splitting only right or down), labels it `<short>-dashboard` (`pane.rename`), swaps it above the boss (`pane.swap`), and gives focus back. herdr's swap focuses the pane it moves in the boss's tab, which keeps that focus for the user's next visit, and switches to that tab: so a swap that happened focuses the boss again, then the pane that had focus when it was not the boss (`pane.focus`, QA #96 N1). The label comes first, so a swap that fails still leaves a dashboard the next run finds; a swap herdr declines (`changed: false`) is a failure too. It is best effort: what it could not do is `dashboard_error` beside the result, never a refusal, and it runs under the workforce lock, so two runs open one, on 5 s of the op's budget, before the agents start: a split, label, swap or focus those 5 s end is out of time, while the layout's read before them, which every op shares, stays a herdr failure. A worker's tab label ends in `-<n>`, so the dashboard is never taken for one. The split needs no team: the dashboard finds its own by the workspace its pane is in (A24). Only `team up` opens one; prefix+d still opens more.
- **The tdaddy preflight** (part 6) has its bullets in A34, not here: it is a package of its own, which lands ahead of the parts that call it.

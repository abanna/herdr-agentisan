# ADR-001 A30. Messages are delivered by name, once the team poll vouches for it

*Adds to:* A2 (delivery, and the crash and timeout rules) and A35 ("messages go to the agent name"). *Narrows:* A2's "delivers it with `agent.prompt` to the recipient's current pane": the dispatcher types by the name herdr knows the recipient's agent by, and the team poll proves the name. Part 1, recorded with NERD-5256 PR 2; part 2 (`send`, sender identity, pane senders) comes with PR 3. Verified against the herdr source at v0.9.5.

- **The dispatcher.** The daemon types each queued message into its recipient with `agent.prompt`, never setting `wait`: with it herdr would answer only once the agent reached a status, long after `CallTimeout`. It runs beside the team poll and makes a pass after every poll, and whatever queues a message wakes it too. One prompt is in flight at a time.
- **The target is a name.** A worker is typed to by its logical id, a tabs team's boss by `<short>-boss`, and the ◆ spaces' boss by `boss` (A7). herdr resolves the name and types in one step, so a pane id it reissued (A35) is never typed into.
- **The name check.** A name is not proof: any agent can take one. A message is claimed only while the last poll's model has an agent of the target's name where it belongs: for a worker, on the pane its row binds by terminal; for a boss, on a pane in its team's boss place, the `<short>-boss` tab or ◆ boss. Otherwise its messages wait. The model is at most one poll old, the window A18 and A35 accept.
- **Every poll replaces the model.** A poll whose pane, workspace or tab list failed leaves none, one whose agent list failed names no agent, and one that could not read the rows binds no worker. Each holds every message it cannot vouch for until the lists answer again, never typing on the last good lists.
- **The first reconcile.** A model that binds and names a worker comes from a poll that reconciled the rows first (A35). So no worker is typed into before the first reconcile since the daemon started: a row a herdr restart left behind names a terminal no pane has.
- **Holds.** The store's claim takes nothing for a worker whose handoff is pending (I3), whose row is lost (no pane is proven, A35) or starting (no agent is ready), or whose binding has ended.
- **How a prompt ends.**
  - *Delivered:* herdr answered `agent_prompted`.
  - *Queued again:* herdr refused before typing a byte (`agent_not_found`, `agent_target_ambiguous`, `agent_blocked`, `agent_not_ready`, `empty_agent_prompt`), or nothing reached herdr: the dial failed, or A3's check refused the socket. It is tried at the next pass, each attempt counted, with no cap; a refusal ends that recipient's turn in the pass.
  - *Failed:* anything else may have come after the text was typed: herdr's `timeout` or `agent_prompt_failed`, a code it adds later, an exchange broken after the write, no answer within `CallTimeout`. The message is failed and its sender sent a notice with the body, in one transaction, and it is never retried.
- **Crash.** A daemon fails every row left `dispatching` as it starts, before anything can claim one, whether or not it runs the team poll. A write recording how a dispatch ended that itself fails leaves the row dispatching, holding its recipient's queue, until that next start: nothing is typed twice.
- **Stop.** Once a message is claimed, a stop cuts short neither the prompt (`CallTimeout`, 5 s) nor the write after it (`store.BusyTimeout`), so a stop never turns a deliverable message into a failure. The pass then ends.
- **Return to the boss.** Each pass first gives every ended binding's queue to its project's boss: a worker retired, failed or gone, or its id bound again at a later generation. The messages keep their ids and order. Retire and spawn leave messages alone. A project no team is configured for keeps its queue.
- **What is typed.** A message the daemon sent is typed as its body, which starts `[agentisan` and invites no reply. Any other is `[msg <ulid> from <sender>] <body>`, which the recipient can reply to. One returned to the boss says whom it was for: `[msg <ulid> from <sender>, originally to <worker>] <body>`, or `[agentisan] originally to <worker>: <body>` for the daemon's.
- **The cleaning.** herdr types the text as one bracketed paste where the agent enabled it, and as raw bytes otherwise. So CRLF and CR are typed as LF, LF and TAB as they are, and every other C0 and C1 control and DEL not at all, ESC included: no body can end the paste early or press a key. Format characters stay, so an emoji joined by ZWJ stays whole. The store keeps the body as sent. An agent without bracketed paste takes each LF as Enter.
- **Logging.** A wait or a refusal is logged at warn when it begins, then at debug while it lasts, until its reason changes or the recipient has nothing queued.
- **Not in part 1.** `send` and its op, sender identity, delivery to a pane (such a message waits), the message events (`agentisan.message.queued`, `.delivered`, `.failed` and `.returned`, which land together), and the switch of the role briefs to `send`.

# ADR-001 A30. Messages are delivered by name, once the team poll vouches for it

*Adds to:* A2 (delivery, and the crash and timeout rules) and A35 ("messages go to the agent name"). *Narrows:* A2's "delivers it with `agent.prompt` to the recipient's current pane": the dispatcher types by the name herdr knows the recipient's agent by, and the team poll proves the name. Part 1 was recorded with NERD-5256 PR 2, and part 2 (`send`, sender identity, pane senders) with PR 3. Verified against the herdr source at v0.9.5.

- **The dispatcher.** The daemon types each queued message into its recipient with `agent.prompt`, never setting `wait`: with it herdr would answer only once the agent reached a status, long after `CallTimeout`. It runs beside the team poll and makes a pass after every poll, and whatever queues a message wakes it too. One prompt is in flight at a time.
- **The target is a name.** A worker is typed to by its logical id, a tabs team's boss by `<short>-boss`, and the ◆ spaces' boss by `boss` (A7). herdr resolves the name and types in one step, so a pane id it reissued (A35) is never typed into.
- **The name check.** A name is not proof: any agent can take one. A message is claimed only while the last poll's model has an agent of the target's name where it belongs: for a worker, on the pane its row binds by terminal; for a boss, on a pane in its team's boss place, the `<short>-boss` tab or ◆ boss. Otherwise its messages wait. The model is at most one poll old, the window A18 and A35 accept.
- **Every poll replaces the model.** A poll whose pane, workspace or tab list failed leaves none, one whose agent list failed names no agent, and one that could not read the rows binds no worker. Each holds every message it cannot vouch for until the lists answer again, never typing on the last good lists.
- **The first reconcile.** A model that binds and names a worker comes from a poll that reconciled the rows first (A35). So no worker is typed into before the first reconcile since the daemon started: a row a herdr restart left behind names a terminal no pane has.
- **Holds.** The store's claim takes nothing for a worker whose handoff is pending (I3), whose row is lost (no pane is proven, A35) or starting (no agent is ready), or whose binding has ended.
- **How a prompt ends.**
  - *Delivered:* herdr answered `agent_prompted`.
  - *Queued again:* herdr refused before typing a byte (`agent_not_found`, `agent_target_ambiguous`, `agent_blocked`, `agent_not_ready`, `empty_agent_prompt`), or nothing reached herdr: the dial failed, or A3's check refused the socket. It is tried at the next pass, each attempt counted, with no cap; a refusal ends that recipient's turn in the pass.
  - *Failed:* anything else may have come after the text was typed: herdr's `timeout` or `agent_prompt_failed`, a code it adds later, an exchange broken after the write, no answer within `CallTimeout`. The message is failed and its sender sent a notice with the body, in one transaction, and it is never retried.
- **Crash.** A daemon fails every row left `dispatching` as it starts, before anything can claim one, whether or not it runs the team poll. A write recording how a dispatch ended that itself fails leaves the row dispatching, holding its recipient's queue, until that next start: nothing is typed twice.
- **Stop.** Once a message is claimed, a stop cuts short neither the prompt (`CallTimeout`, 5 s) nor the write after it (`store.BusyTimeout`), so a stop never turns a deliverable message into a failure. The pass then ends.
- **Return to the boss.** Each pass first gives every ended binding's queue to its project's boss: a worker retired, failed or gone, or its id bound again at a later generation. The messages keep their ids and order. Retire and spawn leave messages alone. A project no team is configured for keeps its queue.
- **What is typed.** A message the daemon sent is typed as its body, which starts `[agentisan` and invites no reply. Any other is `[msg <ulid> from <sender>] <body>`, which the recipient can reply to. One returned to the boss says whom it was for: `[msg <ulid> from <sender>, originally to <worker>] <body>`, or `[agentisan] originally to <worker>: <body>` for the daemon's.
- **The cleaning.** herdr types the text as one bracketed paste where the agent enabled it, and as raw bytes otherwise. So CRLF and CR are typed as LF, LF and TAB as they are, and every other C0 and C1 control and DEL not at all, ESC included: no body can end the paste early or press a key. Format characters stay, so an emoji joined by ZWJ stays whole. The store keeps the body as sent. An agent without bracketed paste takes each LF as Enter. A text whose last token, the run after its last white space, starts with `@` or `$` is typed with one space after it (NERD-5505): Codex opens its file or mention popup on such a token once the paste lands, and the popup would take herdr's Enter, leaving the text in the draft while the message is recorded delivered. Claude and Codex trim the space, and any other text is typed as it is.
- **Logging.** A wait or a refusal is logged at warn when it begins, then at debug while it lasts, until its reason changes or the recipient has nothing queued.
- **Events.** `agentisan.message.queued`, `.delivered`, `.failed` and `.returned`, in `docs/telemetry.md`. None carries a body.
- **Part 2: `send`.** `herdr-agentisan send <to> <body|->` asks the daemon's `send` op, which queues the message through the store, records `.queued` and wakes the dispatcher. The op has a 10 s budget, and like the workforce ops it refuses `not_ready` until the team poll's first reconcile, and exists only while the poll runs. It answers with the message's id and state and whom it took the message to be to and from. Its refusals are `unknown_recipient`, `unknown_sender`, `too_large` and `bad_request`, and, before it asks, `caller_unverified` (A64). The command prints one JSON object on every path and exits 1 when refused.
- **The sender.** The op reads it from one read of herdr's panes, workspaces, tabs and agents and the workers rows (A35). It is the worker a live row binds to the caller pane's terminal; else, for a pane in a team's boss place, that team's boss; else the pane itself, by its terminal. The command confirms its own pane by its lineage, as `team status` does. `HERDR_AGENTISAN_WORKER` counts only when no pane is confirmed and a live row has that id. Under Codex, either counts only from the pane's own Codex (A64). With neither, `send` is refused `unknown_sender`, since a notice would have nowhere to go. There is no authentication: the trust is `herdr agent prompt`'s.
- **The recipient.** `boss` is the sender's own team's boss; from a sender in no team it is `unknown_recipient`. A configured team's boss is also addressed by its name. Anything else is a worker's logical id, which needs a live row: a worker `worker spawn` did not start has none and is refused, so it is reached with `herdr agent prompt`.
- **Pane senders.** A sender that is only a pane is kept by its terminal, which herdr never gives another pane, and its notices are typed into the pane that shows that terminal when the dispatcher serves them, by its pane id from a list of the panes made then. A terminal no pane shows fails them at once. A pane where herdr finds no agent refuses them before typing, and they wait at most an hour, then fail. A notice that fails sends none. A herdr live handoff or restart gives every pane a new terminal (A35), so the pane senders' notices then pending fail. No migration: a pane address's id is now a terminal id.
- **Codex.** A Codex worker in the default sandbox cannot connect to a Unix socket, so it cannot `send`, nor run `herdr agent prompt`. It receives, and its turns reach the boss through the daemon's notices.
- **Not in A30.** Switching the role briefs to `send`, which the companion issue does once the team is spawned through `worker spawn`.
